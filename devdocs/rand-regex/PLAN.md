# Plan: rand_regex Rust CLI Exercise

## Summary

Add `bin/rand-regex`, a project-local Rust CLI around
[`kennytm/rand_regex`](https://github.com/kennytm/rand_regex). Generate one or
more random matching strings with optional deterministic seeding, bounded open
repeats, ASCII character-class parsing, JSON Lines framing, or arbitrary-byte
hex output. Keep the wrapper close to `rand_regex::Regex` and
`regex_syntax::ParserBuilder`; do not add rejection sampling or unsupported
assertion semantics.

## Verified Upstream Facts

- `rand_regex 0.19.0` is the current crates.io release, published February 24,
  2026 from commit `32b513d424dd062abbc5fa3930cbde02310bf9e1`. The repository
  is MIT-licensed, passively maintained, has active CI, and supports Rust 1.85+.
- The crate archive checksum recorded by Cargo is
  `79e745eeef604742ec751000e44d91cdc0552aacacb2c74bee88cc7685918cfa`.
  Pin `rand_regex = "=0.19.0"`, `rand = "=0.10.0"`, and the directly used
  `regex-syntax = "=0.8.9"` in the root Cargo package.
- `Regex::compile(pattern, max_repeat)` parses the Rust `regex` dialect and
  returns a Rand distribution. `max_repeat` is the maximum *extra* repetition
  used for `*`, `+`, and `{n,}`; it does not limit already bounded repeats.
- `Regex::with_hir()` permits deliberate parser configuration. The CLI uses it
  for ASCII mode and byte mode rather than rewriting regex source.
- The distribution implements sampling for `String`, `Vec<u8>`, and
  `EncodedString`. `EncodedString` lets the CLI detect non-UTF-8 output without
  panicking.
- Anchors and word-boundary assertions are rejected because they consume no
  generated bytes. Unsatisfiable regexes and parser errors are distinct upstream
  failures.
- Unicode character classes are enabled by default. In particular, `\d` can
  generate decimal digits outside ASCII. ASCII mode disables Unicode classes;
  byte mode also disables UTF-8 enforcement.
- This is random sampling, not enumeration or uniform sampling across complete
  regex languages. The wrapper adds no uniqueness promise.

## CLI Contract

```text
Usage: rand-regex [OPTIONS] [PATTERN]

  -i, --input FILE          Read the complete regex; use - for stdin
  -n, --count NUMBER        Number of samples; default 1
      --seed U64            Seed generation reproducibly
      --max-repeat NUMBER   Maximum extra open repetitions; default 20
      --ascii               Use ASCII Perl character classes
      --bytes               Parse bytes and emit lowercase hex
      --jsonl               Emit one {"value":...} object per sample
  -V, --version             Print CLI and dependency versions
```

Accept exactly one complete strict-UTF-8 pattern from argv, `--input`, or
nonterminal stdin. Pattern files are not line-oriented and are not trimmed.

Default text output writes each sampled string and LF. Because a generated value
may itself contain LF, use `--jsonl` for unambiguous text framing. `--bytes`
changes parser settings and writes two lowercase hex digits per generated byte,
plus LF; it conflicts with ASCII and JSONL modes.

With `--seed`, initialize one `StdRng` and sample it repeatedly. Without a seed,
use Rand's thread-local generator. Build the complete output before writing so
generation errors do not leave partial stdout. Broken stdout pipes are quiet.
Clap misuse exits 2; input, syntax, unsupported assertion, unsatisfiable regex,
non-UTF-8 text output, and write failures exit 1 with a `rand-regex:` diagnostic.
